# Glossary

Terms used across the Betterplan skills.

- **Endeavor** — the whole project/undertaking being planned in Betterplan.
- **Story Map** — visual structure of the endeavor (Jeff Patton). Left→right = major steps; top→bottom = importance/options. Holds Initiatives and Epics; Stories hang under Epics.
- **Initiative** — a large goal that sets direction. Not implemented directly.
- **Epic** — a sub-goal under an Initiative; a step the user takes toward the goal. Structure, not implemented directly.
- **User Story** — a concrete, buildable option for how a user takes a step. Delivers user value.
- **Project Story** — cross-cutting work with no direct user value (organizational, hardware, docs, recording decisions/events).
- **Devteam Story** — cross-cutting technical work internal to the dev team (refactoring, build pipeline, tech debt).
- **Workitem** — smallest unit, belongs to a Story, used only on the Iteration Board to coordinate delivery. No story points.
- **Release** — a meaningful delivery milestone; Stories are assigned to it. Shown on Story Map (swimlanes) and Delivery Timeline.
- **Backlog** — Kanban view of all Stories organized by maturity level. Where prioritization happens.
- **Iteration (Sprint)** — a fixed, recurring time box (e.g. two weeks) for focused work.
- **Discovery / Delivery (Dual Track)** — exploration (what to build) and implementation (building it) run in parallel within one Story.
- **Maturity levels** — Idea → Draft → Ready (Discovery), Todo → Doing → Done (Delivery), then Closed.
- **Open / Closed** — a Story is Open while in progress, Closed when finished or deliberately stopped.
- **Story Points** — relative effort estimate on a Story. Feeds the Delivery Timeline forecast. Workitems have none.
- **Velocity** — work a team typically completes per iteration; Betterplan averages the last three iterations.
- **Delivery Timeline** — Gantt-style forecast computed from prioritization, estimates, and velocity. Not placed manually.
- **Product Owner** — decides what gets built next and why; owns backlog prioritization.
- **Stakeholder** — anyone with an interest in the outcome who is not implementing it.
